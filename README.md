# video_tg

Приватный телеграм-бот: присылаешь ссылку на видео — получаешь его же
с русской закадровой озвучкой от Яндекса, готовое к скачиванию.

Перевод и синтез речи делает бэкенд Яндекса через
[FOSWLY/vot-cli](https://github.com/FOSWLY/vot-cli). Видео качает `yt-dlp`,
склейку делает `ffmpeg`. Отправка файлов до 2 ГБ — через локальный сервер
Telegram Bot API; что не влезло — прямой ссылкой через nginx.

## Что умеет

| | |
|---|---|
| ссылка без команды | MP4: русская озвучка поверх приглушённого оригинала (громкость в конфиге, по умолчанию 10%) |
| `/audio <ссылка>` | только русская дорожка, MP3 |
| `/subs <ссылка>` | только субтитры, SRT |
| `/orig <ссылка>` | MP4, оригинал заглушён полностью |
| `/q720 <ссылка>` | разово понизить качество до 720p |

Плюс: последовательная очередь с прогрессом в одном редактируемом сообщении,
отмена задач, кэш по ID видео, автоматическая выдача больших файлов ссылкой,
белый список по `user_id`.

Площадки: YouTube (основная), Vimeo, VK, Rutube, Twitch, Coub, Bilibili,
Dailymotion, Одноклассники, Mail.ru, Rumble, BitChute, PeerTube, Odysee,
Twitter/X, Reddit, TikTok, Loom, Udemy, Coursera и ещё несколько десятков —
всё, что поддерживает `vot.js`. Незнакомая ссылка не отвергается: бот
попробует и честно скажет, если не вышло.

## Как устроено

```
              Telegram
                 │
        ┌────────┴─────────┐
        │  telegram-bot-api │  локальный сервер, лимит отправки 2 ГБ
        └────────┬─────────┘
                 │  внутренняя docker-сеть
        ┌────────┴─────────┐        подпроцессы
        │       bot        │────►  vot-cli · yt-dlp · ffmpeg
        │  Python/aiogram  │
        └────────┬─────────┘
                 │
        ┌────────┴─────────┐        /data
        │      nginx       │        ├── tmp/     рабочие каталоги задач
        │  /dl/<token>/…   │        ├── cache/   готовые результаты
        └──────────────────┘        ├── files/   выложенное по ссылкам
              наружу                ├── logs/
                                    └── db.sqlite3
```

Наружу торчит только nginx. Bot API и внутренний HTTP-эндпоинт бота
доступны исключительно внутри docker-сети.

### Путь одной задачи

```
ссылка → whitelist → нормализация URL → поиск в кэше
   ├── попадание → отдать сразу (по file_id, без диска и трафика)
   └── промах    → очередь → метаданные (yt-dlp -J)
                            → перевод (vot-cli, опрос с backoff)
                            → русская дорожка
                            → видео (yt-dlp)
                            → склейка (ffmpeg amix + dynaudnorm)
                            → отправка или ссылка
                            → запись в кэш, уборка временных файлов
```

Перевод запрашивается **до** скачивания видео: если Яндекс этот ролик
не переводит, это выяснится за полминуты, а не после гигабайта трафика.

## Установка с нуля на Ubuntu 24.04

Нужен сервер с root-доступом. GPU не требуется, всё считается на CPU.
Подойдёт и Ubuntu 22.04 — скрипт установки определяет релиз сам.

Минимум: 1 ядро, 1 ГБ RAM **плюс 2 ГБ swap**, 10 ГБ свободного диска.
На такой машине всё работает, но настройки под неё нужно оставить как есть —
см. [Сервер, занятый другими сервисами](#сервер-занятый-другими-сервисами)
и [Маленький диск](#маленький-диск).

### 1. Положить проект на сервер

```bash
sudo mkdir -p /opt/video_tg && sudo chown "$USER:$USER" /opt/video_tg
```

Скопируй файлы проекта в `/opt/video_tg` (через `git clone`, `scp` или `rsync`),
затем перейди в каталог:

```bash
cd /opt/video_tg
```

### 2. Запустить установщик

```bash
sudo bash scripts/install.sh
```

Скрипт поставит Docker и compose v2 из официального репозитория Docker
(в репозиториях Ubuntu лежит старый `docker.io` без compose v2), создаст
каталоги данных с правильным владельцем и сделает `.env` и `config.yaml`
из примеров. Повторный запуск ничего не ломает и не перетирает уже
заполненные конфиги.

### 3. Получить токен бота

Напиши [@BotFather](https://t.me/BotFather) команду `/newbot`, ответь на
вопросы, скопируй токен вида `123456789:AAH...`.

### 4. Получить api_id и api_hash

Это **не** токен бота — это доступ к Telegram API, нужный локальному серверу
Bot API. Одна пара годится для любого числа ботов.

1. Зайди на <https://my.telegram.org> своим номером телефона
2. **API development tools**
3. Создай приложение (название и краткое имя — любые, например `video_tg`)
4. Скопируй `api_id` и `api_hash`

### 5. Узнать свой user_id

Напиши [@userinfobot](https://t.me/userinfobot) — он ответит числом.
Либо запусти бота с временным `allowed_user_ids: [0]`, отправь ему `/id`
и посмотри свой ID в логе (`docker compose logs bot | grep access_denied`).

### 6. Заполнить конфиги

См. следующий раздел.

### 7. Собрать и запустить

```bash
docker compose build
```

```bash
docker compose up -d
```

Первая сборка занимает 3–7 минут.

## Что заполнить в конфигах

### `.env` — секреты и параметры compose

```ini
BOT_TOKEN=123456789:AAH…          # от @BotFather
TELEGRAM_API_ID=1234567           # с my.telegram.org
TELEGRAM_API_HASH=0123456789ab…   # оттуда же
APP_UID=1000                      # id -u
APP_GID=1000                      # id -g
HTTP_PORT=                        # свободный порт для раздачи файлов
```

`HTTP_PORT` умышленно без значения по умолчанию: привычный порт 80 на сервере
часто уже занят веб-сервером, VPN или прокси. Посмотри, что свободно, открой
выбранный порт в файрволе и укажи его же в `public_base_url`:

```bash
ss -tuln | grep LISTEN
```

`APP_UID`/`APP_GID` должны совпадать с владельцем каталога `./data` на хосте,
иначе результаты будут недоступны для правки снаружи контейнера. Узнать свои:

```bash
id -u && id -g
```

Файл содержит секреты — закрой его от посторонних:

```bash
chmod 600 .env
```

### `config.yaml` — поведение бота

Обязательны к правке ровно два параметра:

```yaml
telegram:
  allowed_user_ids:
    - 123456789          # ← твой user_id

links:
  public_base_url: "http://<адрес сервера>:<HTTP_PORT>"   # ← свой адрес и порт
```

Порт в `public_base_url` нужен, только если `HTTP_PORT` не равен 80. Значения
должны совпадать, иначе ссылки на большие файлы будут вести в никуда.

Бот не стартует, пока в `public_base_url` осталась заглушка и пока
`allowed_user_ids` пуст — это сделано намеренно, чтобы не обнаружить
проблему в момент прихода первого трёхгигабайтного файла.

Если раздача больших файлов не нужна вообще, поставь `links.enabled: false` —
тогда `public_base_url` не проверяется.

Всё остальное в [config.example.yaml](config.example.yaml) имеет разумные
значения по умолчанию и подробный комментарий к каждому параметру. Часто
меняют вот эти:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `ffmpeg.original_volume` | `0.10` | громкость оригинала под озвучкой; `0` = как `/orig` |
| `ytdlp.max_height` | `1080` | потолок качества |
| `ytdlp.max_duration_minutes` | `240` | отсечка по длине; `0` — без лимита |
| `cache.ttl_hours` | `168` | сколько держать результаты (7 суток) |
| `cache.max_size_gb` | `50` | потолок кэша на диске |
| `links.ttl_hours` | `24` | сколько живёт выложенный по ссылке файл |
| `vot.lively_voice` | `false` | живые голоса Яндекса вместо синтеза |
| `logging.level` | `INFO` | `DEBUG` печатает командные строки утилит |

### Опционально: cookies для YouTube

Нужны для роликов с возрастным ограничением и когда YouTube начинает
требовать «Sign in to confirm you're not a bot». Экспортируй cookies
в формате Netscape расширением браузера, положи файл и укажи путь:

```bash
cp ~/cookies.txt ./data/cookies.txt
chmod 600 ./data/cookies.txt
```

```yaml
paths:
  cookies_file: "/data/cookies.txt"
```

### Опционально: HTTPS

Ссылки на большие файлы работают и по HTTP, но лучше включить TLS:

```bash
sudo apt install -y certbot
```

```bash
docker compose stop nginx && sudo certbot certonly --standalone -d video.example.com
```

```bash
sudo cp -rL /etc/letsencrypt/live/video.example.com/. ./nginx/certs/ && docker compose start nginx
```

Затем в [nginx/nginx.conf](nginx/nginx.conf) раскомментируй блок `server`
для 443, в [docker-compose.yml](docker-compose.yml) — проброс порта 443 и
монтирование `./nginx/certs`, а в `config.yaml` поменяй `public_base_url`
на `https://video.example.com`.

## Запуск и проверка

```bash
docker compose up -d
```

```bash
docker compose ps
```

Все три сервиса должны быть `running`, а `bot` — ещё и `healthy` спустя
минуту.

```bash
docker compose logs -f bot
```

В логе при успешном старте будут строки `tool_found` (четыре штуки:
vot-cli, yt-dlp, ffmpeg, ffprobe), `database_ready`, `using_local_bot_api`,
`bot_identified`, `queue_started`, `httpapi_started`, `application_started`.

Дальше напиши боту `/start`, потом пришли ссылку на короткий ролик
с YouTube. Сообщение о прогрессе должно пройти стадии
«читаю информацию» → «Яндекс переводит» → «качаю видео» → «склеиваю» →
«отправляю» → «готово».

Остановка (текущая задача будет доведена до конца, до 30 минут):

```bash
docker compose down
```

## Команды бота

| Команда | Что делает |
|---|---|
| `/start`, `/help` | справка |
| `/audio <ссылка>` | только русская дорожка, MP3 |
| `/subs <ссылка>` | только субтитры, SRT |
| `/orig <ссылка>` | видео, оригинал заглушён полностью |
| `/q720 <ссылка>` | разово понизить качество до 720p |
| `/queue` | что сейчас в работе и что ждёт |
| `/cancel <id>` | отменить задачу (без аргумента — если она одна) |
| `/stats` | кэш, очередь, место на диске |
| `/cleanup` | освободить место: удалить файлы кэша, протухшие ссылки, временные каталоги |
| `/id` | твой user_id и id чата |

Команду можно отправить **ответом** на сообщение со ссылкой — тогда саму
ссылку писать не нужно: `/audio` в ответ на сообщение с YouTube-ссылкой.

Под сообщением о прогрессе есть кнопка «🚫 Отменить» — то же, что `/cancel`.

## Настройка

### Громкость оригинала

`ffmpeg.original_volume` — доля от исходной громкости под русской озвучкой.
`0.10` = 10%. Смешивание идёт через `amix` с `normalize=0`, поэтому значение
означает ровно то, что написано, а не «десять процентов от чего-то
поделённого».

`0` работает так же, как режим `/orig` — оригинал не подмешивается вовсе.

### Качество

`ytdlp.max_height` задаёт потолок. Команда `/q720` разово использует
`ytdlp.low_height`. Шаблон выбора формата (`ytdlp.format_template`) можно
переписать под себя — обязательна лишь подстановка `{height}`.

### Время ожидания перевода

Яндекс переводит асинхронно и на первый запрос отвечает «жди N секунд».
Бот опрашивает его с экспоненциальной задержкой, а не фиксированным `sleep`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `vot.attempt_timeout_sec` | `180` | таймаут одной попытки |
| `vot.total_timeout_sec` | `3600` | общий бюджет ожидания |
| `vot.backoff_start_sec` | `20` | первая пауза |
| `vot.backoff_factor` | `1.5` | множитель |
| `vot.backoff_max_sec` | `120` | потолок паузы |

Часовая лекция обычно переводится за 10–20 минут и укладывается с запасом.
Если ролики регулярно не успевают — увеличивай `total_timeout_sec`.

Прерванная по таймауту попытка ничего не теряет: состояние перевода живёт
на стороне Яндекса и привязано к ссылке, следующая попытка подхватывает ту же
задачу.

### Сервер, занятый другими сервисами

Стек по умолчанию настроен так, чтобы уступать всему остальному на машине:
VPN, прокси, чужому боту. Ничего дополнительно включать не нужно.

Два независимых уровня:

**Между контейнерами** — в [docker-compose.yml](docker-compose.yml).
`cpu_shares` 64–128 против обычных 1024, то есть примерно в восемь-шестнадцать
раз меньший вес при дележе процессора. Это относительный вес, а не потолок:
пока соседи простаивают, бот берёт ядро целиком и отдаёт мгновенно, как только
им понадобится. Плюс жёсткий потолок `cpus` (ffmpeg на одном ядре выедает его
полностью, и даже при низком весе соседи чувствуют задержки планировщика) и
`oom_score_adj` 500–800 — при нехватке памяти ядро убьёт этот стек, а не VPN.

**Внутри контейнера** — секция `priority` в конфиге. Подпроцессы vot-cli,
yt-dlp и ffmpeg запускаются через `nice -n 15` и `ionice -c 3`, то есть
работают только тогда, когда процессор и диск никому больше не нужны.

Потолки памяти: бот 384 МБ (+1152 МБ swap на пики склейки), Bot API 160 МБ,
nginx 48 МБ. Суммарно около 590 МБ, остальное остаётся соседям.

Отдельно — сеть: `ytdlp.rate_limit: "5M"` не даёт скачиванию двухгигабайтного
видео забить канал, который делят VPN-клиенты.

Проверить, что бот действительно уступает:

```bash
docker stats --no-stream
```

Если хочется отдать ещё меньше — уменьшай `cpus` у сервиса `bot`, но помни,
что склейка от этого пропорционально замедлится.

**Swap обязателен** на машине с 1 ГБ памяти, иначе сборка образа может упасть
на `npm install`:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### Маленький диск

Дефолты рассчитаны на VPS с диском 15 ГБ, где под систему занято ~6 ГБ.
Если у тебя так же — менять ничего не нужно, всё уже настроено.

Почему это вообще проблема. Во время обработки часового ролика в 1080p
на диске **одновременно** лежат исходное видео (~2.4 ГБ), русская дорожка
(~55 МБ) и результат склейки (ещё ~2.4 ГБ). Пиковая потребность — примерно
2.5× размера исходника, а не его размер. Час в 1080p требует около 5.9 ГБ.

Защита выстроена в пять слоёв:

| Когда | Что происходит |
|---|---|
| старт бота | если свободно меньше `disk.min_free_gb` — громкое предупреждение в лог |
| постановка задачи | проверка нижнего порога, отказ до любых скачиваний |
| после метаданных | оценка по длительности и качеству; отказ с советом использовать `/q720` или `/audio` |
| скачивание | yt-dlp получает `--max-filesize`, вычисленный из остатка места, и отказывается качать неподъёмное сам |
| во время задачи | фоновый монитор; при падении ниже `disk.abort_free_gb` задача прерывается, процессы убиваются, временные файлы вычищаются |

**Главный параметр — `cache.keep_files_after_send: false`** (так и стоит
по умолчанию). Сразу после подтверждённой отправки в Telegram файл на диск
не сохраняется вообще: в кэш пишется только `file_id`. Повторная выдача того
же ролика остаётся мгновенной — она идёт по `file_id` с серверов Telegram,
минуя диск полностью. Место освобождается в ту же секунду, как файл ушёл.

Файлы, отданные прямой ссылкой, удаляются через час после скачивания
(`links.delete_after_download`), а не через 12 часов по TTL.

Посмотреть текущее состояние — `/stats`, там полоска заполнения и вердикт.
Освободить место вручную — `/cleanup`: удаляет файлы кэша, протухшие ссылки
и временные каталоги, но **сохраняет `file_id`**, так что уже переведённые
ролики по-прежнему отдаются мгновенно.

Если диска ещё меньше, скажем 10 ГБ всего:

```yaml
ytdlp:
  max_height: 720           # 720p вместо 1080p — вчетверо меньше места
cache:
  max_size_gb: 1
  ttl_hours: 24
disk:
  min_free_gb: 2.0
  reserve_gb: 1.0
  abort_free_gb: 0.5
links:
  ttl_hours: 6
```

Проверить, сколько места реально свободно:

```bash
df -h / && du -sh ./data/*
```

### Кэш

Ключ — `площадка:video_id:режим[:качество]`. Одна и та же лекция, присланная
как `youtu.be/X`, `youtube.com/watch?v=X&t=42` и `m.youtube.com/…`, отдаётся
из кэша.

Хранится и файл, и `telegram file_id`. При переполнении `cache.max_size_gb`
файл удаляется, а `file_id` остаётся: повторная отдача идёт мгновенно и вообще
без диска.

### Очередь

`queue.concurrency: 1` — последовательная обработка. Код поддерживает больше,
но Яндекс плохо реагирует на параллельные запросы с одного адреса.

`queue.shutdown_grace_sec` (1800) — сколько ждать завершения текущей задачи
при остановке контейнера. Должно быть **меньше** `stop_grace_period` в
[docker-compose.yml](docker-compose.yml) (1860s), иначе Docker прибьёт
контейнер раньше срока.

## Обновление

### yt-dlp (самое частое)

Площадки ломают парсинг заметно чаще, чем выходят релизы всего остального.
Девять из десяти проблем «видео не качается» лечатся этим:

```bash
./scripts/update.sh
```

Обновление ставится внутрь работающего контейнера и переживёт перезапуск,
но **не** пересборку образа. Чтобы закрепить — впиши новую версию в
[requirements.txt](requirements.txt) и сделай полное обновление.

### Полная пересборка

```bash
./scripts/update.sh --full
```

Подтянет свежие `telegram-bot-api` и `nginx`, пересоберёт образ бота,
перезапустит всё (текущая задача будет доведена до конца) и покажет версии
всех утилит в новом образе.

### Смена версии vot-cli

```bash
./scripts/update.sh --vot 2.1.0
```

Запишет версию в `.env` и пересоберёт образ. **Перед этим** сверься
с [README vot-cli](https://github.com/FOSWLY/vot-cli): между мажорными
версиями набор флагов менялся, и может потребоваться правка
`app/pipeline/vot.py`.

### Обновление кода бота

```bash
git pull && docker compose build bot && docker compose up -d
```

Схема базы мигрируется автоматически при старте (`PRAGMA user_version`).
Откат на более старую версию образа с новой базой не пройдёт — бот скажет
об этом явно.

## Проверить перед первым запуском

Ниже — то, что я **не смог подтвердить** чтением README и исходников
vot-cli. Всюду реализован автоматический запасной путь, так что бот
поедет в любом случае, но если что-то ведёт себя странно — смотри сюда.

**1. Ведёт ли себя `--preview` так, как ожидается.**
Бот сначала просит у vot-cli прямую ссылку на дорожку (`--preview`), не
скачивая её. Если ссылку не удалось разобрать дважды подряд, он **сам**
переключается на режим скачивания в файл (`--outdir`) и ищет результат
перебором расширений. В логе это видно как `vot_preview_unusable`. Если
такое происходит всегда — просто поставь `vot.use_preview: false`, это
штатный режим, а не деградация.

**2. Точная схема JSON у `--preview`.**
Из исходников `client.ts` известны поля `input, status, type, videoId, url,
outputPath`, но что именно лежит в `url` в режиме preview — прямая ссылка
на mp3 или ссылка на страницу — однозначно не читается. Разбор сделан
рекурсивным: бот обходит весь JSON и берёт первое значение, похожее на
ссылку или существующий путь, из ключей `url/outputPath/output/path/file`.
Плюс запасной вариант — голая ссылка регуляркой из stdout.

**3. Требует ли `--lively-voice` обязательного `--api-token`.**
В README vot-cli оба флага перечислены рядом, но не сказано, обязателен ли
OAuth-токен Яндекса. По умолчанию `vot.lively_voice: false` — обычная
озвучка доступна всегда и работает без токенов. Если включишь живые голоса
и получишь ошибку авторизации, нужен `vot.api_token`.

**4. Работает ли `--preview` вместе с `--subs`.**
Не оговорено нигде. Для субтитров запасной путь тот же, что в пункте 1.

**5. Принимает ли твоя сборка `telegram-bot-api` пути `file://`.**
Режим `telegram.use_file_uri: true` отдаёт локальному серверу путь к файлу
вместо HTTP-загрузки — для 2 ГБ это разница между секундами и минутами.
Поддержка заявлена в Bot API, но поведение конкретной сборки стоит проверить.
Если сервер откажется, бот один раз залогирует `file_uri_rejected`,
переключится на обычную загрузку и больше пробовать не будет до
перезапуска. Чтобы не пробовать вовсе — `use_file_uri: false`.

**6. `--subs-format=srt`.**
Флаг документирован (`json`, `srt`, `vtt`), но проверить вживую я не мог.
Если субтитры приходят не в том формате — поменяй `vot.subs_format`.

Отдельно: **синтаксис флагов с `=`** (`--outdir=path`, а не `--outdir path`)
подтверждён примерами в README vot-cli и используется везде.

## Диагностика

### Бот не стартует

**`Ошибка конфигурации: … неизвестный параметр`**
Опечатка в имени ключа `config.yaml`. Точное место указано в сообщении.
Сверься с [config.example.yaml](config.example.yaml).

**`links.public_base_url не заполнен — там осталась заглушка`**
Подставь адрес, по которому сервер доступен снаружи, и порт из `HTTP_PORT`.
Если раздача больших файлов не нужна — `links.enabled: false`.

**`задай HTTP_PORT в .env`**
Compose не стартует без явно выбранного порта. Посмотри свободные
(`ss -tuln | grep LISTEN`), открой нужный в файрволе, впиши в `.env`.

**`telegram.allowed_user_ids пуст`**
Впиши свой `user_id`. Узнать: [@userinfobot](https://t.me/userinfobot).

**`Не найдены внешние утилиты: …`**
Образ собран неправильно:

```bash
docker compose build --no-cache bot && docker compose up -d
```

**`ОШИБКА: не найден файл конфигурации /config/config.yaml`**
Нет `config.yaml` рядом с `docker-compose.yml`:

```bash
cp config.example.yaml config.yaml
```

**`нужно задать TELEGRAM_API_ID в .env`**
Нет `.env` или он не заполнен: `cp .env.example .env`, затем впиши значения
с <https://my.telegram.org>.

### Бот стартовал, но не отвечает

**Молчит на любое сообщение.**
Твоего `user_id` нет в белом списке. Бот отвечает молчанием намеренно —
чтобы не подтверждать посторонним, что он существует. Проверь:

```bash
grep '"event":"access_denied"' ./data/logs/bot.log | tail -5
```

Там будет твой настоящий `user_id` — впиши его в `allowed_user_ids`
и перезапусти: `docker compose restart bot`.

**`Logged in as a bot elsewhere` / `Unauthorized`.**
Бот уже работал через облачный `api.telegram.org`, и Telegram не отдаёт
сессию локальному серверу. Разлогинься на облаке и перезапусти:

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/logOut"
```

```bash
docker compose restart telegram-bot-api bot
```

**`Cannot connect to host telegram-bot-api:8081`.**
Сервер Bot API не поднялся. Смотри его лог:

```bash
docker compose logs telegram-bot-api | tail -30
```

Чаще всего — неверные `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` в `.env`.

### Ошибки при обработке

**«Яндекс отказал в переводе на этапе создания сессии».**
В логе vot-cli это выглядит как `Failed to request create session`, причём
`Getting video data` при этом проходит успешно. Проверь, повторяется ли отказ
на заведомо переведённом ролике:

```bash
docker compose exec bot vot-cli --lang=en --reslang=ru --preview "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
```

Если отказ приходит и здесь — дело не в видео, а в адресе сервера: Яндекс
блокирует диапазоны хостингов. Лечится прокси:

```yaml
vot:
  proxy: "http://user:pass@адрес:порт"
```

Подойдёт любой HTTP или SOCKS-прокси, лучше всего с российским адресом.
Проверить конкретный прокси до правки конфига:

```bash
docker compose exec bot vot-cli --proxy="http://адрес:порт" --lang=en --reslang=ru --preview "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
```

Тот же ролик стоит проверить с домашнего компьютера — если там переводится,
а на сервере нет, это окончательно подтверждает блокировку по адресу:

```bash
npx vot-cli@2.0.1 --lang=en --reslang=ru --preview "https://www.youtube.com/watch?v=dQw4w9WgXcQ"
```

**«Яндекс не смог перевести этот ролик».**
Штатная ситуация: в видео нет речи, язык оригинала не поддерживается,
либо ролик слишком длинный для их бэкенда. Проверить, дело ли в боте:
открой ролик в Яндекс Браузере и нажми кнопку перевода. Если и там не
переводится — бот ни при чём.

**«Яндекс не отдал перевод за N мин».**
Длинные лекции иногда переводятся дольше бюджета. Пришли ссылку ещё раз
через несколько минут: перевод к тому моменту обычно готов и придёт сразу.
Либо увеличь `vot.total_timeout_sec`.

**«Не удалось скачать видео» / `Sign in to confirm you're not a bot`.**
Первым делом обнови yt-dlp:

```bash
./scripts/update.sh
```

Если не помогло — нужен файл cookies (см.
[раздел про cookies](#опционально-cookies-для-youtube)). YouTube применяет
такие проверки к серверным IP заметно чаще, чем к домашним.

**«Видео недоступно».**
Приватное, удалено, с возрастным ограничением или закрыто в регионе сервера.
Для возрастных ограничений помогают cookies. Для региональных — `ytdlp.proxy`
в конфиге.

**«Не получилось склеить видео».**
Смотри лог:

```bash
grep -E '"event":"(ffmpeg_mux_start|job_failed)"' ./data/logs/bot.log | tail -5
```

Если причина в кодеке — включи `ffmpeg.allow_video_transcode: true`
(по умолчанию включено). Перекодирование на CPU идёт долго, под него
отдельный увеличенный таймаут `ffmpeg.transcode_timeout_sec`.

**«На диске не хватит места для этого ролика».**
Проверка сработала до скачивания — ничего не потрачено. Варианты по
возрастанию радикальности: `/q720` (вчетверо меньше), `/audio` (десятки
мегабайт), `/cleanup` (освободить кэш). Текущее состояние — `/stats`.

**«Место на диске закончилось прямо во время обработки».**
Сработал фоновый монитор: задача остановлена, процессы убиты, временные
файлы вычищены — диск не забился под ноль. Так бывает, когда оценка
оказалась заниженной (ролик с необычно высоким битрейтом). Сделай
`/cleanup` и повтори через `/q720`.

**Место кончается регулярно.**

```bash
df -h / && du -sh ./data/*
```

Проверь `cache.keep_files_after_send` — он должен быть `false`, иначе
результаты копятся на диске. Затем уменьшай `cache.max_size_gb`,
`cache.ttl_hours` и `links.ttl_hours`, либо понизь `ytdlp.max_height`
до 720. Подробнее — в разделе [Маленький диск](#маленький-диск).

**`/cleanup` отвечает «сейчас идёт обработка задачи».**
Уборка может забрать файлы, которые нужны работающей задаче. Дождись
завершения (`/queue`) или отмени её (`/cancel <id>`).

**Озвучка расходится с видео к концу.**
Бот предупреждает об этом сам, если расхождение больше
`ffmpeg.sync_tolerance_sec`. Причина в дорожке от Яндекса, а не в склейке:
она иногда приходит длиннее или короче исходника. Штатного лечения нет.

### Проблемы с файлами и ссылками

**Файл ушёл ссылкой, хотя должен был влезть в Telegram.**
Проверь `telegram.max_upload_bytes` (должно быть `2000000000`) и
`telegram.use_local_api: true`. При `use_local_api: false` лимит 50 МБ.

**Ссылка отвечает «Ссылка недействительна».**
Одноразовая ссылка уже использована (плюс окно `links.one_time_grace_min`,
по умолчанию час) или истёк `links.ttl_hours`. Попроси файл заново.
Если такое происходит регулярно посреди скачивания — увеличь
`one_time_grace_min` или поставь `one_time: false`.

**Ссылка не открывается вообще.**
Проверь, что порт открыт и nginx жив:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://<твой-адрес>/nginx-health
```

Должно быть `200`. Если нет — смотри `docker compose logs nginx` и правила
файрвола (`sudo ufw status`). Проверь также, что `links.public_base_url`
совпадает с реальным адресом и портом.

**Скачивание обрывается на середине.**
Проверь `links.one_time_grace_min`: браузеры тянут большой файл несколькими
Range-запросами, и каждый проходит проверку токена. Часа по умолчанию хватает
на 2 ГБ даже на медленном канале, но если канал совсем плохой — увеличь.

**Отправка в Telegram висит и падает по таймауту.**
Увеличь `telegram.upload_timeout_sec`. Если включён `use_file_uri`, проверь,
что `./data` смонтирован в контейнер `telegram-bot-api` по тому же пути
`/data` — иначе сервер не найдёт файл. Это в
[docker-compose.yml](docker-compose.yml), менять не нужно, но проверить стоит.

### Очередь и перезапуски

**Задача висит в «Яндекс переводит» много минут.**
Это нормально для длинных роликов. Прогресс попыток виден в логе:

```bash
grep '"event":"vot_attempt"' ./data/logs/bot.log | tail -10
```

**После перезапуска задача вернулась в очередь.**
Так и задумано: `recover_interrupted()` возвращает недоделанные задачи
и правит то же сообщение.

**`docker compose down` висит долго.**
Бот дожидается текущей задачи (до `queue.shutdown_grace_sec`, по умолчанию
30 минут). Если ждать не нужно:

```bash
docker compose kill bot && docker compose down
```

Временные файлы всё равно будут вычищены при следующем старте.

**Очередь переполнена.**
`queue.max_pending` (20 по умолчанию). Отмени лишнее через `/queue`
и `/cancel <id>`.

### Общая проверка состояния

```bash
docker compose ps && docker stats --no-stream
```

```bash
curl -s http://127.0.0.1:8080/healthz
```

(последнее — только изнутри сети; снаружи эндпоинт недоступен, для проверки
из хоста используй `docker compose exec bot curl -s http://127.0.0.1:8080/healthz`)

## Принятые решения

Решения, принятые без уточняющих вопросов, — по одной строке на каждое.

**Выбран upstream `FOSWLY/vot-cli`, а не форк `vot-cli-live`.** Главное
преимущество форка — живые голоса — уже есть в upstream (`--lively-voice`),
а второе, `--merge-video`, не нужно: склейка делается своим ffmpeg-конвейером,
где есть полный контроль над громкостью, нормализацией и копированием
видеопотока. При этом upstream активнее (релиз 2.0.1 от июля 2026 против
последнего коммита форка в декабре 2025) и парсит площадки через отдельно
обновляемый `@vot.js/*`. Переключиться на форк можно правкой `vot.flavor: live`
и `vot.binary` в конфиге — код поддерживает оба набора флагов.

**Выбран aiogram 3, а не python-telegram-bot.** У aiogram локальный Bot API —
first-class: `TelegramAPIServer.from_base_url(..., is_local=True)` и отдача
файла по пути вместо multipart-загрузки, что для 2 ГБ решающе.

**SQLite, а не Postgres.** Один пользователь, последовательная очередь;
отдельный контейнер БД был бы лишней движущейся частью.

**Перевод запрашивается до скачивания видео.** Если Яндекс ролик не переводит,
это выясняется за полминуты, а не после гигабайта трафика.

**Таймаут попытки vot-cli трактуется как «ещё не готово», а не как ошибка.**
vot-cli внутри себя опрашивает бэкенд бесконечно и молча, поэтому опрос вынесен
на уровень бота: попытка с таймаутом, убийство группы процессов, backoff,
повтор. Фиксированного `sleep` в коде нет.

**`--outfile` не используется**, вместо него `--outdir` + `--no-title` и поиск
результата перебором расширений: названия роликов бывают с эмодзи и слешами,
а неясность с расширением у `--outfile` перебор снимает совсем.

**Одноразовость ссылки — это один сеанс скачивания, а не один HTTP-запрос.**
Браузеры тянут большой файл несколькими Range-запросами; токен, сгорающий
после первого, обрывал бы загрузку на втором. Отсюда `one_time_grace_min`.

**Content-Disposition в nginx не выставляется.** Имя файла браузер берёт из
последнего сегмента URL (percent-encoded UTF-8) — русские названия скачиваются
корректно, а заголовок с кириллицей их бы сломал.

**Один образ на бот, vot-cli, yt-dlp и ffmpeg.** Они работают с общим временным
каталогом; растащить по контейнерам можно, но гигабайты пришлось бы гонять
через общий том без выигрыша.

**Бот работает не от root.** Entrypoint от root делает только `chown` на
`/data` (bind-mount приезжает с правами хозяина хоста) и сразу сбрасывает
привилегии через `gosu`.

**Healthcheck у `telegram-bot-api` не задан.** В образе нет ни curl, ни wget;
проверка, всегда возвращающая успех, врала бы в `docker compose ps`.

**vot-cli ставится через npm, а не бинарником с GitHub Releases.**
Воспроизводимая версия и любая архитектура.

**yt-dlp обновляется отдельным быстрым режимом `update.sh`.** Площадки ломают
парсинг чаще, чем выходят релизы бота.

**Заглушки в конфиге не проходят валидацию.** Незаполненный `public_base_url`,
пустой `allowed_user_ids` и отсутствующий `HTTP_PORT` — ошибка старта, а не
сюрприз при первом большом файле.

**Никаких адресов и портов в репозитории.** Ни IP, ни домена, ни номера порта
по умолчанию: всё выбирается под конкретный сервер и живёт только в `.env`
и `config.yaml`, которые в git не попадают.
